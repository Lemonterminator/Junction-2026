## 1. Track Definition & Reorganization Criteria

**AI Infrastructure Track (by Verda)** focuses on the underlying compute power, inference services, cloud-native foundations, edge computing architectures, and energy-efficient/trustworthy engineering systems that support modern AI and data-intensive applications.

### Reorganization Criteria
This catalog selects **20 representative challenges** from all 147 historical hackathon challenges across Hack Junction 2017–2025 (with comprehensive coverage of all `AI & Data` related challenges, and cross-track inclusion of underlying infrastructure challenges from `Sustainability`, `Urban & Mobility`, `Entertainment`, and `Health`) that align with the following four technical dimensions:

1. **Serverless Model Inference and AI API Platforms**: e.g., Featherless.ai serverless open-source model inference platform, ElevenLabs speech synthesis inference foundation, TrueFace.ai deep learning visual recognition API.
2. **Cloud-Native Compute, GPU/TPU Clusters, and Data Infrastructure**: e.g., Google Cloud machine learning and GPU/TPU compute foundation, Aiven managed cloud-native open-source data streaming and storage infrastructure, SAS Viya cloud-native analytics engine, Microsoft Azure data science foundation.
3. **Edge Computing, 5G Networks, and Device-Side/WebGPU High-Performance Computing Foundations**: e.g., SUSE Akraino/uMEC telecom edge k3s cluster, Sensofusion microsecond-level event camera edge streaming visual inference, Veikkaus WebGPU/WebWorker browser-side GPU parallel computing, Nokia/Ericsson 5G low-latency edge networks, Huawei wearable device-side real-time inference framework.
4. **Green Computing, Trustworthy Inference Architectures, and High-Throughput Network Monitoring Foundations**: e.g., Outokumpu pluggable lightweight large models and inference energy estimation architecture, CGI green low-energy software engineering, BNB Chain real-time on-chain data indexing protocol, Ericsson core network signaling anomaly detection pipeline, Cisco DNA Center network application performance monitoring foundation.

### 11. [2025] Sensofusion — Lights, Camera, Reaction!

- **File**: [2025_Sensofusion_Lights_Camera_Reaction.md](./2025_Sensofusion_Lights_Camera_Reaction.md)
- **Original Track**: `AI & Data` | **Sub-theme**: III. Edge Computing, 5G Networks & On-Device/WebGPU High-Performance Computing Foundation (Edge Computing, 5G & On-Device/WebGPU Runtime)
- **Core Theme**: Microsecond-level asynchronous event camera streaming data ingestion and ultra-low-latency edge vision inference
- **Classification Rationale**: Targets microsecond-level pixel-level asynchronous event streams that break through traditional frame rate limits, building real-time processing and low-latency machine vision inference pipelines, placing extremely high demands on streaming perception and edge inference infrastructure.

#### Description

Operate in a timescale where ordinary vision fails - machine vision on microsecond timescales.

There's a camera type you might have never heard about – an Event Camera. They use an imaging sensor that detects changes in light intensity at the pixel level, producing a stream of asynchronous events rather than full frames. Their key advantages include very high dynamic range, low latency (microseconds), minimal motion blur, and high temporal resolution. Can you figure out how to use such a camera to detect objects that move extremely fast? Prove it.

You’ll get hands-on access to professional event cameras equipped with various lenses - all available on-site at Junction.
Your mission: build real-time AI or ML models that can detect and interpret motion from these microsecond-level vision streams.
Start simple: can you count how many times per second a fan spins? Then push further - track drones, estimate speed, predict motion, whatever you can imagine. 
Push these sensors beyond their limits — and remember, their limits are very high.

#### Resources

Access to several professional event cameras installed on-site at Junction. 
APIs and documentation for data access and integration.

Mentors from Sensofusion R&D team with deep expertise in vision technology and AI.

Example scripts and data samples to help teams get started.

#### Prizes

Winning team, as chosen by the Sensofusion mentors, will be rewarded with DJI Mini 3 drones. Every member of the winning team will get a drone.

### 16. [2024] Outokumpu — Sustainable generative AI assistant for insights

- **File**: [2024_Outokumpu_Sustainable_generative_AI_assistant_for_insights.md](./2024_Outokumpu_Sustainable_generative_AI_assistant_for_insights.md)
- **Original Track**: `Sustainability` | **Sub-theme**: IV. Green Compute, Trustworthy Inference & Telemetry Infra
- **Core Theme**: Pluggable Model Architecture, Energy-Efficient Inference Optimization for Small Models, and Query-Level Energy/Carbon Estimation
- **Classification Rationale**: Derived from the Sustainability track, it explicitly requires designing a lightweight architecture with hot-swappable (interchangeable) model components rather than relying on brute-force stacking of ultra-large models and ultra-long contexts, and quantitatively estimating the inference compute and energy cost per LLM query, perfectly aligning with Verda's green and efficient AI infrastructure philosophy.

#### Description

Your challenge, should you accept it, is to build a sustainable AI assistant for dynamic information retrieval and summarization to support business critical use cases. As Sustainable AI is a very broad topic, to keep things simple, for this challenge we would like to focus on two aspects of Sustainable AI: trustworthiness and efficiency (which we are using here as a proxy for ecological sustainability, through more limited energy use and carbon footprints). So this is not “just” about building an information retrieval assistant and feeding huge amounts of data to an enormous model – that is easy. We want you to build a system that accomplishes the same but in a very trustworthy and sustainable way, and that makes things quite a bit more challenging… so you need to work smart not just hard on how you accomplish the task, as “bruteforcing” this will not result in the desired outcome. But hey, that’s why this is called a challenge, we know you are up for it!\
\
Trustworthiness has also a few different aspects. Firstly, it is about using the right data – as correct information as possible as the source. We all know that the internet is not necessarily always correct… so how do you know what sources to trust? But even when you have the right information, summarizing that might not always get you what you want either. One of the fairly common challenges of generative models is hallucinations, effectively inventing results to questions where there are none. This leads to a lack of trust and can even be a barrier to usage. You should strive to build a system that bases the outputs on sources you can trust and avoids hallucinations to ensure the outputs of the system are reliable and trustworthy.\
\
Furthermore, as we know, large language models are quite resource intensive. Especially training models tends to consume large amounts of energy, but also interference (when you use the models) can be costly – especially when done at scale. As it is not in scope for this challenge to build a model from scratch, let’s focus on the computational costs related to using an existing model – both in terms of which model to choose and how we use it. This is something we can often control better in practical applications too, as even if we use existing large models, we can definitely decide which ones to use and how we use them. So while this is a very exciting set of technologies, we should use them wisely and avoid excessive resource consumption. Less is definitely more in this context – and the best solution probably does not use the biggest model or the broadest context possible (or very large amounts of queries to a model – it is the total cost that counts) – and a big part of the challenge is to optimize the resource usage while still getting great results.\
\
This solution, if successful, can make a huge difference – and shed light on how tasks like can be accomplished in a sustainable way. So it is not just about building something very cool and useful but showcasing how thinking about of the sustainability of AI can make a real positive difference!\
\

We will have people onsite to answer questions (detailed hours to be communicated later) and ability to reach out for questions via asynchronous means (email or other digital channels). We will also be available for meetings to discuss and answer questions.\
