## 一、赛道定义与重组标准 (Track Definition & Reorganization Criteria)

**AI Infrastructure Track (by Verda)** 聚焦于支撑现代人工智能与数据密集型应用的底层算力、推理服务、云原生底座、边缘计算架构与高能效/可信工程体系。

### 重组与归类标准（Reorganization Criteria）
本目录从 Hack Junction 2017–2025 全部 147 道历史赛题（重点覆盖 `AI & Data` 全部相关赛题，并跨赛道吸纳 `Sustainability`、`Urban & Mobility`、`Entertainment`、`Health` 中的底层设施赛题）中，筛选出符合以下四大技术维度的 **20 道代表性挑战**：
1. **Serverless 模型推理与 AI API 平台**：如 Featherless.ai 无服务器开源模型推理平台、ElevenLabs 语音合成推理底座、TrueFace.ai 深度学习视觉识别 API。
2. **云原生算力、GPU/TPU 集群与数据基础设施**：如 Google Cloud 机器学习与 GPU/TPU 算力底座、Aiven 托管式云端开源数据流与存储基础设施、SAS Viya 云原生分析引擎、Microsoft Azure 数据科学底座。
3. **边缘计算、5G 网络与端侧/WebGPU 高性能计算底座**：如 SUSE Akraino/uMEC 电信边缘 k3s 集群、Sensofusion 微秒级事件相机边缘流式视觉推理、Veikkaus WebGPU/WebWorker 浏览器端 GPU 并行计算、Nokia/Ericsson 5G 低时延边缘网络、Huawei 穿戴端侧实时推理框架。
4. **绿色算力、可信推理架构与高吞吐网络监控底座**：如 Outokumpu 可插拔轻量化大模型与推理能耗估算架构、CGI 绿色低能耗软件工程、BNB Chain 实时链上数据索引协议、Ericsson 核心网信令异常检测流水线、Cisco DNA Center 网络应用性能监控底座。

### 6. [2021] Aiven — 可持续数据基础设施

- **单题档案**: [2021_Aiven_Sustainable_Data_Infrastructure.md](./2021_Aiven_Sustainable_Data_Infrastructure.md)
- **原始赛道**: `Sustainability` | **所属子方向**: 二、云原生算力、GPU/TPU 集群与数据基础设施 (Cloud Compute, GPU/TPU & Data Infrastructure)
- **核心主题**: 云原生开源数据基础设施（数据库/消息队列）与数据中心碳足迹度量
- **归类理由**: 源自 Sustainability 赛道，由云数据基础设施厂商 Aiven 出题，既提供 API 驱动的自动化云端数据底座，又直击全球数据中心与算力基础设施的能耗与碳足迹对比。

#### 挑战描述

随着公开可用的数据越来越多，我们越来越有可能以更高的准确性和更广的范围来计算由计算和数据基础设施产生的碳足迹及其他形式的环境影响。

计算机在全球范围内消耗大量电力，其中大部分消耗发生在世界各地的数据中心。得益于云原生技术，迁移云提供商的阈值从未如此之低。我们请求你帮助我们让其他人更容易选择最可持续的方式来运行他们的数据基础设施。

你能否找到一种方法，让人们可视化他们的选择如何影响环境？目标是实现消费者的“环境竞争”——不仅根据价格，还根据对环境的负担来比较服务和商品。

挑战在于提出一种工具，能够针对历史记录数据，提供关于人们选择的环境影响的易懂且有洞察力的反馈，并支持未来预测。你应该使其易于与其他服务和网站集成。

#### 可用资源

Aiven 团队随时为你提供帮助。

有些人讨厌从事运维工作，但我们热爱它。Aiven 是云原生开源数据基础设施解决方案的领导者：数据库、消息队列、容错存储等等。在我们的帮助下，开发者可以做他们最擅长的事：创建出色的应用程序。同时，我们做我们最擅长的事：管理云数据基础设施。

活动期间，Aiven 将为你提供免费基础设施（以积分形式）和专家建议，用于构建你的数据处理管道。我们基于 API 的简易服务配置将帮助你自动化基础设施的设置——我们也可以在这方面帮助你。

可信度也有几个不同的方面。首先，它关乎使用正确的数据——尽可能正确的信息作为来源。我们都知道互联网不一定总是正确的……那么你如何知道哪些来源可信？但即使你拥有正确的信息，对其进行摘要也可能并不总能得到你想要的结果。生成模型相当常见的挑战之一是幻觉，实际上是为没有答案的问题编造结果。这会导致缺乏信任，甚至可能成为使用的障碍。你应该努力构建一个系统，使其输出基于你可以信任的来源，并避免幻觉，以确保系统的输出可靠且可信。

此外，众所周知，大型语言模型非常消耗资源。特别是训练模型往往消耗大量能源，但推理（当你使用模型时）也可能成本高昂——尤其是在大规模进行时。由于本次挑战的范围不包括从头构建模型，让我们聚焦于使用现有模型相关的计算成本——包括选择哪个模型以及如何使用它。这也是我们在实际应用中通常可以更好地控制的事情，因为即使我们使用现有的大型模型，我们绝对可以决定使用哪些模型以及如何使用它们。因此，尽管这是一组非常令人兴奋的技术，我们应该明智地使用它们，避免过度的资源消耗。在这种情况下，少即是多——最好的解决方案可能不会使用最大的模型或最广泛的上下文（或对模型进行非常大量的查询——总成本才是关键）——挑战的很大一部分是在仍然获得出色结果的同时优化资源使用。
