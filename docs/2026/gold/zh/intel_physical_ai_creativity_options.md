# Intel Physical AI：创意方案与实施顺序

更新：2026-11-13。基于 [仓库筛选](../../silver/zh/open_edge_platform_repositories.md)
和 [比赛指南](../../silver/zh/intel_physical_ai_studio_guide.md)。下文均为方案建议；
没有完成算法集成、真实模型性能测试或机械臂验证。

## 建议优先：给一个样例，识别、质检并分拣同类物体

流程：参考图框选 -> Instant Learn 分割同类物体 -> Anomalib 检查物体 ROI ->
动作选择 -> Studio 训练策略 -> SO-101 分拣 -> 重新观察确认结果。

现场可展示框选、分割结果、异常热图、动作决定和执行结果。先选已有策略能稳定抓取
的一类物体；少样本分割不会自动赋予新形状、新姿态的抓取能力。
ROI 的裁剪/缩放、正常样本训练和测试输入必须一致；否则分割模块可能改变异常分布。
分割置信度、异常分数和抓取结果应分别保存，不能混成一个未经校准的置信度。

验证条件：先用录制帧验证分割，再比较完整图/ROI 异常检测效果；随后记录单物体
分拣成功率、物体偏移/杂乱场景表现、推理延迟与完整周期，确认增加模块的实际收益。

## 同期工具：可测量的 Intel 优化展示

复用 Edge AI Sizing Tool 的进程监测或 CLI 输出，结合应用自己的计时与任务结果。
在相同输入、策略和场景下对比 CPU 与受支持 GPU/NPU 配置；记录设备、模型版本、
精度、预热与采样次数。监控利用率本身不能证明能耗下降或分拣更快，功耗/温度需要
额外可用的测量源。该工具的 Ubuntu 26.04 与新硬件兼容性仍需实际检查。

## 进阶：多视角桌面状态

闭环稳定后，评估 Scenescape 的固定相机标定和场景数据，跟踪待检区、合格区、
异常区之间的物体转移。新增多相机融合不等于自动获得毫米级抓取坐标；需验证空间
标定误差和端到端延迟。移动腕部相机位姿接入另行评估。

另一个可独立尝试的行为是：检测不确定时移到已验证的复检姿态，再采图检查。
这需要我们实现状态机、示教姿态、重试上限和失败处理；Scenescape 不自动提供该行为。

## 实施顺序与退出条件

1. Studio 启动、设备校准、示教录制、训练、真机运行；先证实已有工具链可用。
2. Anomalib 正常样本与阈值基线，打通自动分拣及结果观察；不确定结果能停止或复检。
3. 增加 Instant Learn，小样本离线验证有收益后再接真实闭环；失败时保留原有输入路径。
4. 性能对照与演示记录；闭环稳定且有剩余时间时才增加多相机融合或视频流水线。

此排序基于工程依赖与演示价值，不按有冲突的评分表推算确定得分。
主线代码建议放在本项目 `src/`；当前尚未创建控制实现。
