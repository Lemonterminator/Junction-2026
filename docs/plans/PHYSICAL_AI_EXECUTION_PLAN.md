## 1. 目标、依据与交付范围

目标：交付 PDF 第 9 页的四项必交付：SO-101 闭环原型、Anomalib 结果被 VLA 实际使用、Core Ultra Series 3 上的 OpenVINO 部署、讲清架构和优化决策的现场演示。执行关键路径为 **现场标定 → 遥操作验证 → Studio 录制 → Studio 管理训练 → Intel 部署 → 真实评估**。twin 只在主体通过后安排 G3a 回放；Gemini、RL 与接触动力学研究延期。

本计划把[历年赢家复用研究](../research/PAST_HARDWARE_WINNERS_REUSE.md)转化为工作包，不把历史获奖与本项目效果直接关联。赛题依据为 [Intel Gold 分析](../2026/gold/en/intel_physical_ai_challenge.md)及其引用的原始 brief；PDF 与 GitHub 的评分表仍有冲突，应确认最终要求，不能按其中一张表推断必胜路径。

## 4. 目标架构与数据契约

```text
单一相机所有者 → 带时间戳的 RGB-D/相机参数
                         ↓
         桌面/工件/容器几何 + 工件身份关联
                         ↓
           RGB ROI → Anomalib → 缺陷证据
                         ↓
           分拣意图 → Studio/VLA 策略
                         ↓
              动作检查 → 机械臂适配器
                         ↓
           新观察 → 结果验证 → 工件记录

Studio 录制 → Studio 训练任务 → 5090 远程 trainer → 模型回传/导出
                                                     ↓
                               Intel OpenVINO PhysicalAI 运行时

工件记录/录制轨迹 → 可选 G3a 回放（主体完成后）
```

控制、感知、显示、训练分别运行；相机由一个明确的进程占有。第一步允许显式切换 Studio 与感知的所有权；若同时消费画面，必须先实现并验证共享采集适配器，不能假定 Studio 已能订阅自建帧服务。

### 4.1 共同契约

所有名称为建议，实施前对照当前 Studio 对接点确定；下表不表示已有同名类。

| 数据 | 必需内容 | 不允许的隐式假设 |
| --- | --- | --- |
| `FramePacket` | `frame_id`、`camera_id`、采集/接收时间、RGB/深度、内参、深度尺度、对齐方式、`calibration_id`、有效性 | RGB 与深度天然同坐标；空洞深度等于 0 米物体 |
| `ObjectObservation` | `object_id`、ROI/掩码、相机系位置、已校准时的底座系位置、朝向估计、有效性/质量 | 每帧新轮廓等于一个新任务；相机坐标可直接控制机器人 |
| `DefectDecision` | `normal/defective/uncertain`、原始异常分数、阈值版本、异常图、输入帧、模型版本 | 异常分数等于概率；模型决定的标签就是评估真值 |
| `SortIntent` | `action_id`、工件/观察 ID、目标容器、任务文本、策略版本、允许执行的观察时效 | 任意自然语言都能被现有策略理解；颜色标签天然等于任务规则 |
| `ActionStatus` | 请求/接受/执行/结束时间、设备状态、终止原因、关联 ID | 串口写入成功等于抓取成功；结束命令等于放置成功 |
| `OutcomeEvidence` | 新观察、物体是否离开原位/释放并稳定进入目标区、结果/未知、失败原因、证据帧 | 超时就是成功；夹爪闭合就是抓到了物体 |
| `EpisodeRecord` | 上述引用、配置/数据/模型/校准版本、模式、独立真值、起止时间 | 仿真、回放和真实数据可混合计算同一个成功率 |

同机延迟用单调时钟测量；跨主机记录时钟同步误差或只比较各自主机内耗时，不能直接相减不同主机的单调时间。保存原始时间及对齐规则。状态关联使用 ID，不能只靠文件顺序。

### 4.2 动作生命周期

`OBSERVE → INSPECT → PLAN → EXECUTE → VERIFY → DONE / FAILED / UNKNOWN`；无效或不确定观察可以进入 `REOBSERVE`，达到显式次数/时间上限后停止该工件任务。硬件错误直接停止并报告，不自动重试运动。

每个工件同时最多一个活动动作。重复帧、重复消息、动作超时后的迟到响应不得重复提交任务。停止后的再次动作需要按照仓库要求获得该次运动授权。

### 4.3 Anomalib → SmolVLA：本轮选定的接口

采用确定性规则把缺陷标签映射到 **训练时出现过的固定任务文本**。不让模型临时解释原始异常分数，也不要求它从新的提示词自动学会分拣规则。

| 检测结果 | 配置映射 | 任务示例（按最终规则冻结） |
| --- | --- | --- |
| `normal` | 正常容器 ID → 其稳定视觉名称 | `Pick up the target brick and place it in the green bowl.` |
| `defective` | 异常容器 ID → 其稳定视觉名称 | `Pick up the target brick and place it in the pink bowl.` |
| `uncertain` / 目标不明确 / 数据过期 | 重观察或停止 | 不调用动作生成，不沿用上一次任务 |

示例颜色不是官方规则；现场确定后写入版本化配置。首轮目标放在明确的目标区，干扰物位于区外；若赛题允许任意多目标，必须另行验证指称/目标选择。`object_id` 只是日志关联，文本中的内部 ID 不会自动成为视觉可理解的对象。

录制两种任务时覆盖相近起始位置、姿态与工件外观，避免“左边总进绿碗”一类位置捷径。完整相机图像与关节状态仍按策略训练契约输入；Anomalib 的 ROI 只用于缺陷判断，不能未训练就替换策略图像。把标签、目标容器、最终 task、观察 ID 与模型版本共同写入记录。

适配器将 task 送入实际部署运行时的任务字段，经预处理进入 tokenizer。pinned Studio 的 SmolVLA preprocessor 已处理 `TASK`，但部署适配器仍需验证实际 API、导出预处理及任务更新路径。每个新工件/任务切换时使用运行时支持的 reset 清除旧 action chunk 等策略状态；不在执行一个 chunk 中途偷偷替换任务。

**验收分三层**：① 单元测试验证标签到任务映射、过期/不确定拦截；② 离线集成检查真实 tokenizer 输入与任务变化，确认无旧动作缓存串用；③ 已授权的配对实机测试：相同/匹配起始场景分别给两个任务，看实际放置目标是否改变；正常业务评估则恢复真实检测标签。配对诊断与业务准确率分开报告。只证明 prompt 改变不能通过第③层；若策略忽略指令，先补平衡示教和训练。双策略路由可作对照，但须明确其与语言条件单策略的区别及赛题接受范围。

来源：[pinned SmolVLA preprocessor](../../external/physical-ai-studio/library/src/physicalai/policies/smolvla/preprocessor.py)。

### 4.4 5090 作为 Studio 的训练资源

5090 与 Studio 集成兼容。上游支持后端本机训练及注册远程 trainer；当前 `training.py` 调用 pinned backend 的 `physicalai fit`，属于同源训练代码，但没有自动创建 Studio UI 中的任务记录或完成模型回传。这两种集成程度不能混称。

**首选路线**：现场 Intel 上保留 Studio 项目/设备/录制与数据管理；把独立 Linux/WSL 的 5090 主机准备为可连接的 SSH trainer，通过 Studio Training Targets 注册，由 Models 页面发起任务，检查数据快照上传、任务进度、checkpoint/导出及模型回传。先用微型真实数据跑短任务验证全程，再跑正式训练；WSL 网络、GPU 容器、远程连接与版本兼容仍待验证。

验收证据：Studio 项目/环境/数据集 ID、固定数据快照、训练 job ID、实际 GPU、有效超参数、loss/log、返回模型 ID 与导出文件 hash。不能把截屏作为唯一证据，也不假定已有 CLI TOML 参数会自动导入 UI；对照生成的有效配置核验冻结/精度/相机映射等选项。

若预先约定的 2 人时连接排查预算耗尽仍不能完成短任务，切换已具备条件且获准使用的 Studio Modal 路径；保留 5090 CLI 做诊断/对照。也可评估在 5090 主机运行独立 Studio backend，但数据与模型跨实例传递必须实测。CLI 单独训练的结果只有在记录清楚导出、导入/登记和部署路径后，才能说明实际集成程度；不手工修改 Studio 数据库伪造 job。Modal 账户、额度与任务启动不因本计划而自动获准或完成。

来源：[Studio 训练](../../external/physical-ai-studio/application/docs/06-training-policies.md)、[远程 trainer](../../external/physical-ai-studio/application/docs/07-remote-training.md)、[现有 CLI](../../src/defect_sorter/training.py)。

### 4.5 OpenVINO PhysicalAI 与 Robotics AI Suite 的落点

本轮拟使用 **OpenVINO PhysicalAI 运行时**消费 Studio 导出的策略，Anomalib 推理器输出缺陷标签，自有编排层按 4.3 传递 task，再通过与 SO-101 匹配的运行时/插件执行；控制器、相机继续保持单一所有者。禁止同时运行 Studio Run model 和独立 Runtime 争用同一设备。

pinned Studio README 展示 `physicalai.inference.InferenceModel` 及 `physicalai run --config runtime.yaml`，backend 的 runtime 源固定到 `8381d439c2660d357b4b9d633f28ea7e7ed42c81`。先在该依赖组合上验证导出加载、语言任务、动作缓存重置、设备选择和停止路径，再决定适配器实现；本文不是未经测试即可运行的 runtime 配置。

**Robotics AI Suite** 出现在上游评分项，但名称本身没有说明必须额外部署哪个组件。kickoff 确认所指套件/版本和认可的集成证据，记录实际包、插件、设备与调用路径；不把安装 OpenVINO 或展示商标等同于完成 Suite 集成。不得为了名称临时引入整套与闭环无关的服务。

来源：[上游 event guide](../../external/physical-ai-studio/JUNCTION2026.md)、[运行时示例](../../external/physical-ai-studio/README.md)、[backend 依赖与固定版本](../../external/physical-ai-studio/application/backend/pyproject.toml)。

## 7. 数据缺失时可以立即做什么

| 可以推进 | 需要等待真实数据/设备的工作 |
| --- | --- |
| 契约、状态机、去重、异常路径、日志、假适配器 | 正常/异常阈值、真实缺陷质量、物体关联鲁棒性 |
| 合成几何与坐标变换测试、回放格式 | 相机外参、TCP、关节零位与夹爪映射实测 |
| 已有训练 plan、独立环境 smoke、微型合成数据解码 | 有效示教训练、显存/收敛结论、真实策略成功率 |
| 现成 MJCF 加载、仿真步进、简单场景、接口测试 | 动力学辨识、接触精度、sim-to-real 迁移 |
| Studio trainer 连接、任务映射与基准记录器 | 真实语言条件响应、功耗/温度及鲁棒性结果 |

合成数据的质量、假适配器的成功率、计划中的指标都不写入真实实验结果。真实数据到位后应重新跑依赖项，不自动继承占位实验结论。

收缩顺序：

1. 训练/数据不足：保留一条策略线，减少任务分布；ACT 或脚本只可作为标明范围的对照，不能据此声称满足 VLA 集成要求。
2. 仿真阻塞：交付录制回放与几何误差，明确缺少动力学预测；暂不开展仿真训练。
3. 导出或设备不支持：保留已验证模型及运行设备，记录失败；在可用模型上完成真实 OpenVINO 部署证据。若仍未通过，部署要求保持未完成。
4. 可选功能：G2/G4 未通过就不启动 twin；Gemini/RL 已延期，不通过压缩录制或鲁棒性测试时间来恢复。
5. 实机报错：停止该动作，由现场负责人处理；开发转向离线工作，不能用回放替代真实闭环验收。

## 9. 评估表与最终完成检查

### 9.1 偏移与杂乱场景矩阵

G2a 用于调通基础闭环；G2b 使用冻结模型/阈值后的留出场景，建议四层各 10 次（正常/缺陷各 5），共 40 次。已有基础场景测试满足同一冻结版本与协议时可复用该层样本并注明，不重复计算独立样本数。试验逐次遵守实机授权和停止规则。

| 分层 | 设置 | 要检验的问题 |
| --- | --- | --- |
| A 基础 | 单目标，已定义任务区，无干扰 | 缺陷判断、任务选择与基本抓放 |
| B 位置偏移 | 目标区内未用于训练的平移/旋转，保持可达 | 是否只记住示教位置；两种任务均覆盖 |
| C 杂乱 | 目标区内一个明确目标，区外至少两个不同/相似外观干扰物，使用留出布局 | 目标关联、误抓干扰物、背景引起的异常误报 |
| D 部分遮挡 | 在允许条件下遮挡部分表面，保留可抓区域；目标不可辨识场景另外诊断 | 是否触发重观察/停止；是否错误自信地执行 |

每层建议目标 ≥8/10 正确完成，并报告汇总与各层结果；这只是内部演示目标。停止/未知不算分拣成功，但在预期不可辨识的独立诊断案例中，可以评估“正确拒绝”，不能计入分拣成功分子。设备故障时保留已运行结果并停止，报告未完成场景，不为补足样本继续运动。

固定目标选择、干扰物、位置、缺陷真值和场景清单。按物理工件与会话隔离训练/测试，场景顺序交错两种任务，防止温升与类别混淆。小样本报告分子/分母及局限；用测试结果调参后换新留出集，旧结果转为开发结果。

4.3 的配对任务诊断另表记录：相同/匹配起始场景下两种任务产生对应放置结果。它证明条件行为，不能代替真实缺陷检测评估。
