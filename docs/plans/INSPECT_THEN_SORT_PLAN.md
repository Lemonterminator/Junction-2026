# SO-101：先抓取检查，再按缺陷结果分拣

日期：2026-11-15（Europe/Helsinki）。状态：后续实施计划；本次只编写文档，不改变控制程序、数据集或模型，不授权相机操作和机械臂运动。以下数量、容差和验收线均为建议目标，不是已测结果或赛题规定。

## 1. 技术选择与适用范围

采用第二种方案：**抓取并展示工件 → 保持标准持物姿态 → Anomalib 判定 → 选择绿碗或粉碗放置指令 → 验证实际结果**。目标是让检测结果实际决定本次动作，并能分别定位抓取、检测、技能衔接和放置失败。

| 方案 | 何时选择目标容器 | 优势 | 本场景的主要限制 |
| --- | --- | --- | --- |
| 两条完整任务：抓取、检查、放入绿/粉碗 | 完整任务开始前 | 延续已有完整分拣数据；技能间无额外交接 | 工件拿起后才看见缺陷时，目标选得过早；仍需增加暂停和动态分支 |
| 三条技能：抓取检查、持物放绿、持物放粉 | 检查完成后 | 缺陷证据与动作选择之间有明确边界；可独立训练和验证 | 必须可靠终止检查动作，且检查终点与放置起点分布一致 |

如果工件在桌面上就能可靠检查，两条完整任务仍可作为对照。若第一种方案增加拿起后的检查暂停和容器切换，其运行控制已经接近第二种方案。

首轮限制为单个目标工件、固定机器人底座和相机、明确的检查面、固定两碗布局。先完成这一闭环，再评估位置变化、换碗布局、干扰物和部分遮挡。夹爪遮住的面不能视为已检查；单次抓持旋转不等于六面检查。若规则要求任意面缺陷都可检出，必须另做重抓或多相机覆盖方案，并重新获得运动授权。

当前约定沿用 [sort-v1 数据卡](../datasets/SORT_V1.md)：无十字笔迹为正常，进入 green；有十字笔迹为异常，进入 pink。用户讨论中的 red 在此统一为现有粉碗。若现场确实换为红碗，另建任务/数据版本，同步修改实物、任务文本、映射和验证区域，不把 pink/red 混写进同一个版本。

## 2. 现有能力与实施缺口

本计划以本地源码和 [STATUS](../../memory/STATUS.md) 为依据；历史设备与训练记录没有在本次重新验证。

| 组件 | 现有内容 | 本方案需要补齐 |
| --- | --- | --- |
| `inspection.py` | 单个 RGB crop 的评分、normal/defective/uncertain、Padim 训练及 OpenVINO scorer | 检查视角集合、质量和时效校验、多视角聚合、阈值验证 |
| `closed_loop.py` | observe → inspect → plan → execute → verify；固定的完整抓放指令；`Policy.reset/act/done` 协议 | 检查前抓取、视角事件、持物交接、两条持物放置指令、阶段超时与取消 |
| `episodes.py` / `training_preflight.py` | 完整分拣录制的审查、LeRobot v3 读取、任务文本/索引校验 | 三技能片段切分和血缘信息、持物起点质量校验、分组划分 |
| `motion.py` / `so101_reader.py` | 受限动作检查和设备适配边界 | 由实际部署适配器验证持物保持、动作队列撤销和技能完成信号 |
| Studio/策略运行时 | 已有录制与训练接入；具体状态见团队记录 | 实际 API 的技能切换、reset、取消、图像订阅与导出后任务输入路径 |

`Policy.done()` 是协议要求，不证明 SmolVLA 自动预测“已完成”。当前 `run_episode` 在任何策略运动前评分一次，不能仅靠改 prompt 得到本计划。不得把本计划中的状态、事件和配置字段说成已经存在的 API。

原 `sort-depth-v2` 完整抓放数据和 checkpoint 保留作基线。没有展示检查视角和标准持物交接的旧 episode，不能直接改名冒充检查技能或持物放置示教。

## 3. 三条固定指令与技能契约

建议新数据版本名为 `inspect-sort-v1`；这是建议名，尚未创建 Studio dataset 或配置文件。

| skill_id | 唯一任务文本 | 起点 | 终点与完成证据 |
| --- | --- | --- | --- |
| `pick_inspect` | `Pick up the brick, present it to the front camera for inspection, and hold it there.` | 单砖在约定桌面目标区，夹爪打开，机械臂处于已记录起始范围 | 必需视角已采集，返回标准持物姿态，工件仍在夹爪中，关节稳定 |
| `place_green` | `Place the held brick in the green bowl.` | 同一标准持物姿态及已验证的小范围变化，工件在夹爪中 | 工件释放并稳定进入绿碗，夹爪退出碗口 |
| `place_pink` | `Place the held brick in the pink bowl.` | 与绿碗任务相同的持物状态分布 | 工件释放并稳定进入粉碗，夹爪退出碗口 |

三条技能优先放进一个语言条件 SmolVLA 模型；不是必须训练三个模型。相机、关节状态、任务文本必须共同进入真实推理路径。ACT 没有此处所需的语言输入，若作为对照则按技能分别路由，并明确区别。

“检查”包含一套固定、可复现的展示顺序；只写泛化的 inspect 文本不会自动得到指定视角。操作者先确认哪些面能看清，再录制一致的展示动作，每个有效视角短暂停顿，最后回到同一持物姿态。检查技能中不得包含向某个碗移动的动作。

### 3.1 持物交接条件

现场负责人和集成人员在录制前共同冻结 `handoff_pose_id`：关节目标和单位、允许误差、夹爪范围、工件相对夹爪姿态、画面中的预期位置、桌面和人体安全距离。精确角度由安全的现场示教测量，本文不指定未验证关节值。

建议先以连续 0.5 秒稳定作为候选窗口；位置/速度/夹爪容差、最短静止时间、最大保持时长必须根据读数噪声和已授权的现场试验确定。超过容差、工件滑落、缺少新图像或姿态证据时，不进入放置阶段。夹爪闭合本身不能证明抓取成功。

“暂停”指保持受控持物状态，继续监测状态及设备故障，不是关闭扭矩。保持也有时限；超时进入失败处理，交由现场人员按安全流程接管，不在后台无限保持或自行丢弃工件。

### 3.2 动作队列与阶段完成

检查阶段完成时，由控制器停止接受该阶段新动作，使未执行 action chunk、异步请求和历史状态失效，再启动新技能。建议每阶段使用递增 `stage_generation`，迟到响应即使返回也不得执行。放置开始前调用真实运行时支持的 reset，使用新鲜图像、当前关节状态和选中的固定任务文本重新推理。

终止依据必须来自显式的阶段进度与状态检查：各必需视角事件完成、持物交接条件满足。视角事件可由已验证的姿态/视觉门控产生；人工标注可用于训练准备，但不能在正式自动评估时由人替系统点击“检查完成”。单靠 prompt、固定睡眠、训练集平均时长或模型输出一个动作 chunk 都不能算完成。

## 4. 控制状态机与失败分支

```text
OBSERVE → PICK_INSPECT → HOLD_VALIDATE → SCORE_VIEWS → SELECT_TASK
                                                        │
                                  normal ───────────────┤→ PLACE_GREEN
                                  defective ────────────┤→ PLACE_PINK
                                  uncertain ────────────┘→ REOBSERVE / UNKNOWN
PLACE_GREEN / PLACE_PINK → VERIFY → DONE / FAILED / UNKNOWN
任意阶段：设备故障或急停 → 停止发出新动作，报告并终止本次任务
```

每次仅一个活动工件、一个动作执行者。按 `(cycle_id, object_id, stage_generation)` 关联观察、推理与命令；不会因为重复图片、重复消息或超时后的旧结果再次放置。

| 条件 | 处理 | 禁止行为 |
| --- | --- | --- |
| 未抓起、滑落、姿态不符 | 停止当前技能；记录失败，等待现场处理 | 继续运行持物放置技能或盲目重抓 |
| 某个视角模糊、缺帧或分数缺失 | 在同一保持姿态内重取新画面，受次数和总时限约束 | 把无分数当 normal；复用上个工件分数 |
| 缺少必需面且无法在当前姿态补拍 | 标记 coverage_incomplete，结束为 UNKNOWN | 自动翻转、重抓或宣称全表面正常 |
| 判定有效但等待后过期、工件状态改变 | 判定失效；重新验证当前工件与姿态 | 沿用旧判定发起放置 |
| 放置超时、结果不可见 | FAILED 或 UNKNOWN，按证据区分 | 以指令发送成功替代物理成功 |
| 过载、失联或其他伺服故障 | 停止发出新动作并报告；执行既有可用的安全停止机制 | 自动重试运动、绕过限速或保障措施 |

建议只允许最多两次原地重取图像作为初始软件配置，且不延长最大保持时限；这不包含新的转腕或重抓动作。任何新增运动须遵守 [AGENTS.md](../../AGENTS.md) 的当次授权规则。

## 5. Anomalib 检查协议

### 5.1 图像与覆盖

相机沿用现有单一所有者；从已有采集路径分发图像，不能为了评分再独占打开 front 或 D415。先验证订阅接口及时间戳；若现有路径不提供可用帧，先实现共享采集适配器。策略仍使用训练契约中的完整相机视图，Anomalib 独立使用 RGB 工件 crop。

为每件工件建立检查包：`cycle_id/object_id/view_id/frame_id`、采集与接收时间、crop 坐标、分辨率、曝光配置版本、清晰度/遮挡质量、模型与阈值版本。只在对应视角稳定期间收图，避免末端姿态的一张图替代之前所有面。

建议每个必需面选 3 张不同且有效的稳定帧；帧数、静止/清晰度门槛和时效必须写进版本化配置并用独立验证集选择。重复帧不计为新证据。不可见面单独标缺失，不伪造评分。

### 5.2 判定规则

候选聚合规则：同一面的有效帧分数取中位数得到 `s_view`；各必需面的分数取最大值得到 `s_object`。中位数用于减少单帧噪声，最大值用于让一个有缺陷的面触发异常；规则的实际检出率仍须验证，不能由公式推断有效。

采用两个经验证集冻结的阈值 `t_normal < t_defect`：

- 至少一个有效面的 `s_view >= t_defect`：defective；即使其他面缺失，也记录覆盖不足并允许按已见缺陷拒收。
- 所有必需面都有足够有效新帧，且各面的 `s_view < t_normal`：normal。
- 其他情况，包括缺面、非有限分数、模型异常、阈值间分数或画面过期：uncertain。

异常分数不是缺陷概率。不能默认任意导出的 0.5 都是正确业务阈值，也不能混合原始分数与归一化分数。归一化、输入预处理、视角聚合和阈值必须作为一个版本验证；现有 `decide` 的边界行为及其测试保留，新增多视角逻辑另有明确边界测试。

### 5.3 数据与阈值验证

Padim 用正常工件检查 crop 建模。采集正常工件的不同允许颜色、朝向、面、夹爪外观和光照变化；避免模型只学背景或夹爪位置。标十字的异常工件用于阈值验证和独立测试，不进入正常训练目录。阈值选择集与最终测试集分开。

同一物理工件、同一源循环及其相邻视频帧不能跨 anomaly 训练/验证/测试泄漏；尽量按工件及拍摄会话隔离。工件数量不足时如实写明评估限制。统计单位为工件，不能用几百张近邻帧冒充几百个独立样本。

现有 `train_padim` 帮助路径包含 `train/good` 和 `test/{good,defect}`，不据此假定三路隔离已经实现。实施时检查 datamodule 的真实划分，显式固定验证来源，最终测试数据在阈值冻结前不交给训练/调参流程。

## 6. 录制计划：50 次循环、100 个技能片段

### 6.1 数量与分组

在冻结契约后记录 50 次成功源循环：25 次最终放绿、25 次放粉。每次包含检查片段和放置片段，因此可得到 50 个 `pick_inspect`、25 个 `place_green`、25 个 `place_pink`，共 100 个技能片段。片段不等于独立循环；失败原片另留作诊断，不混入成功示教。

| 源循环分组 | 循环数 | 检查片段 | 绿放置 | 粉放置 | 用途 |
| --- | ---: | ---: | ---: | ---: | --- |
| train | 40（绿/粉各20） | 40 | 20 | 20 | 参数拟合 |
| validation | 6（绿/粉各3） | 6 | 3 | 3 | 选 checkpoint、诊断 |
| test | 4（绿/粉各2） | 4 | 2 | 2 | 离线保留测试；样本很小 |
| 合计 | 50 | 50 | 25 | 25 | 首轮 pilot |

分组先按 `source_cycle_id` 固定，再派生片段：同一循环的检查与放置不得跨组。若使用同一实体工件或同一会话，进一步按实体/会话分组，无法满足上述精确数量时报告真实数量。VLA 的源循环划分与 anomaly 的实体隔离分别检查。

因此“25+25”是总录制预算，预留验证和测试后每个放置技能只有20条用于训练。需要25条训练示教/目的地时必须额外采集。数量不保证收敛；先看独立失败分布再补数据。[SmolVLA 官方文档](https://huggingface.co/docs/lerobot/main/smolvla)把约50个任务 episode 作为起点，不是对本项目或每个技能的充分性保证。

### 6.2 先做 6 次试录，再扩大

先试录 6 次（绿/粉各3）：检查示教可安全重复、全部视角可见、检查终点与两个放置起点一致、原始视频和关节读数可解码、切分后任务文本正确。试录失败先改流程；若改了契约，旧试录不能混进最终版本。契约未变且质量合格的试录可计入50次。

每条录制顺序：

1. 现场操作者获得当次运动授权，确认校准、安全范围和相机所有权；按现有相机锁定流程验证曝光/白平衡，固定底座、相机、碗和检查区域。
2. 在目标区放单砖，记录物理工件 ID、独立缺陷真值、允许检查面、位置/朝向、布局和源循环 ID。
3. 从约定起点抓取、抬起并依次展示各检查面；各面停稳供取图，最终回到标准持物姿态。
4. 在持续受控保持下标记技能边界，检查工件仍在夹爪内。阶段一到此结束，不附带返回桌面或去碗动作。
5. 阶段二从实际交接状态开始，按指定放置文本移动到碗、释放并退出碗口，保存结束证据。
6. 回放并检查视频、关节、时间、任务文本和边界；保留失败原因。操作者在演示采集时指定目的地不算自动闭环评估。

### 6.3 Studio 原始录制与派生数据

优先保存连续源循环，再用明确边界派生成两个技能 episode，避免停止/启动录制导致姿态变化。原始录制使用单独的源循环任务描述；导出的技能片段才标三条固定技能文本，不能把一个完整循环都标成 `pick_inspect`。

切分工具需保留 `source_cycle_id`、源帧范围、技能 ID、交接帧、真值、布局、工件/会话 ID 与版本；重建片段时间、frame/episode/task 索引、视频时间范围及统计量，防止 action chunk 越过技能边界。录制频率、关节顺序/单位、相机键和深度编码保持一致，完整解码校验后再训练。

如果 Studio 当前不能导出正确的技能片段，可在同一持物状态下分别录两条 episode，但必须测量录制间隙的姿态漂移并通过交接条件；不能靠手动移动 follower 来制造起点。无可用的分段/导出工具时，不开始批量录制和长训练。

当前 `episodes.py` 审查完整抓放会期待闭爪、开爪等事件。检查片段不释放、放置片段不重新抓取是正确行为；需要按技能扩展审查规则，不能绕过检查或给片段伪造事件。

### 6.4 变化与防捷径

首轮50次先冻结碗布局，平衡相近的目标位置、朝向、工件颜色与两种目的地。位置先用已验证可达的小范围，不一次铺开所有九宫格、碗布局、角度和遮挡组合。每类变化在两种目的地中都出现。

持物放置技能必须在外观相近的工件上都见到两条指令，避免只靠十字笔迹或工件颜色猜目的地。可增加少量有标注的诊断/技能示教，交叉使用正常/标记工件与绿/粉目的地；这些是指令服从数据，不把反向分拣当作正常业务成功。诊断片段和业务评估分别记录。

第二轮按失败类型补数据：抓取不稳补位置/朝向；交接漂移补真实终点附近起点；指令被忽略补相似状态的双目的地配对；换碗失败再采集布局 B。未训练和验证换碗前，固定布局结果不能声称颜色跟随或布局泛化。

## 7. 训练、运行时与 Intel 部署

1. 为新技能数据单独建数据契约和 recipe；固定数据 hash、split manifest、任务表、相机顺序、关节单位及归一化统计。不得覆盖 `sort-depth-v2` 或修改其两条完整抓放任务语义。
2. 在实际 Studio 训练环境中验证三种任务都经过 tokenizer；先用少量真实片段完整跑通加载、梯度、验证与保存，再安排正式预算。先采用现有 SmolVLA expert 路线，超参数按 [训练指南](../infrastructure/TRAINING.md) 起步，由验证结果调整，不以固定步数承诺质量。
3. 训练采样按技能审查：检查片段可能更长，单看片段数量不能保证绿/粉放置得到足够训练权重。分别报告各技能样本、时长、损失和独立完成率；只在验证集选 checkpoint。
4. 优先使用 Studio 管理的训练任务；若实际采用仓库 CLI，记录其不自动创建 Studio UI job/注册产物的边界。旧手工启动任务的状态需现场只读核实，不能按昨日记录认定已结束。
5. 在 fake cell、录制回放和真实策略适配器层依次验证 reset、取消、阶段事件、新鲜观测和异步迟到响应。协议级 fake 测试通过不代表部署运行时支持热切换。
6. 分别导出和验证 Anomalib 与动作策略。CPU 先作数值参照，再比较目标 GPU/NPU 的配置、编译、实际执行、分数/动作误差与业务判定；发现数值不一致就停止使用该设备结果。
7. 记录设备、模型 hash、输入形状、精度、预处理/阈值版本和计时范围。区分 warm-up、单次推理、排队、检查耗时与全循环耗时；真实数据、回放与 twin 分开。支持 OpenVINO 不等于 NPU 部署成功，单个模型推理更快也不等于整轮更快。

## 8. 按依赖推进的工作包

人员用角色占位；实施前指定现场负责人、数据负责人、控制集成人和检测/训练负责人，可由同一人兼任。

| 顺序 | 负责人角色 | 交付物 | 通过条件 |
| --- | --- | --- | --- |
| W0 冻结契约 | 现场 + 集成 | 检查面定义、三文本、持物姿态、容差/时限和版本 | 不存在“任意面都能看见”或 pink/red 混用的隐含假设 |
| W1 试录与分段 | 数据 + 现场 | 6次试录、源循环/片段清单、解码报告 | 两阶段起止条件满足；三技能可按组加载 |
| W2 检查基线 | 检测 | 正常训练集、独立验证集、固定阈值及多视角规则 | 不完整检查不能判正常；保留每面证据与混淆矩阵 |
| W3 控制器 | 集成 | 阶段状态机、共享帧消费、队列隔离、超时/失败记录 | fake/replay 确定性测试通过，旧动作/旧分数绝不穿过交接边界 |
| W4 pilot训练 | 训练 + 数据 | 50次循环派生数据、三技能checkpoint与分技能报告 | 三任务真实输入可查，源循环不跨组，没有以总loss替代行为验收 |
| W5 设备验证 | 检测 + 集成 | Intel模型/设备数值对比与运行记录 | 每个使用的模型/设备组合均有实际执行和数值证据 |
| W6 实机验收 | 现场 + 全组 | 独立盲测、配对指令诊断、逐次失败记录 | 在新的当次运动授权下完成，按下节报告真实结果 |

W2与W3可在W1契约固定后独立推进；W4依赖分段工具和合格数据。W6依赖控制、训练、检测及设备验证，无现场运动授权时停在离线验证，不自行启动策略。

### 8.1 代码落点与 TDD

优先扩展既有模块；只有出现稳定的新边界时才拆模块，并同步更新 AGENTS 的测试归属表。所有行为变更按 red → green → refactor：先写最小确定性失败测试、确认原因，再改生产代码，跑所属模块和全套。

| 模块 / 归属测试 | 必须覆盖的行为 |
| --- | --- |
| `inspection.py` / `tests/test_inspection.py` | 合成多面分数聚合；阈值相等/临界；模糊或缺面不判正常；重复帧、NaN、过期证据与模型异常 |
| `closed_loop.py` / `tests/test_closed_loop.py` | 三技能顺序；未到交接不放置；两条精确文本映射；旧chunk/迟到结果丢弃；uncertain有界重观察；故障不重试 |
| `episodes.py` / `tests/test_episodes.py` | 技能片段边界、source血缘；检查不要求释放；放置不要求重新抓取；切分不跨阶段采样动作 |
| `training.py` / `training_preflight.py` / `tests/test_training.py` | 三任务索引完整、血缘分组隔离、相机/单位契约、三个split的真实技能覆盖 |
| `motion.py` / `tests/test_motion.py` | fake bus上的动作边界、取消/受控保持、限速与故障处理；测试不连接硬件 |

真实重编码、解码、dataloader、导出 tokenizer 和运行时取消另有离线集成检查；fake 测试不能替代这些检查。计划编写本身不修改上述行为，也不增加镜像实现的测试。

### 9.2 分层实机验收（以后单独授权）

以下数量和线为团队候选门槛，开始前冻结；不是已完成结果，也不构成统计上的量产可靠性证明。

| 层次 | 测试安排 | 候选门槛与证据 |
| --- | --- | --- |
| 检查模型 | 独立工件，正常/异常各至少10件；覆盖允许颜色及检查面 | 固定阈值下报告逐件结果、漏检/误报/uncertain；小样本目标为异常漏检0，不能据此宣称真实漏检率为0 |
| 技能交接 | 至少10次完整抓取检查并交接 | 至少9次达到有效持物交接；旧动作穿越边界、无证据放置和故障重试均为0 |
| 指令诊断 | 至少5组相近持物起点，每组分别给绿/粉指令，共10次 | 目标至少9/10跟随指令；与正常业务分拣结果分开计数 |
| 固定布局闭环 | 20次新测试，正常/异常各10，随机顺序，操作者不选目的地 | 目标至少18/20正确完成；无授权外运动和安全门绕过；逐次保留失败/未知与耗时 |
| 扩展场景 | 位置偏移、布局B、干扰物、可见面受控遮挡分别测试 | 各条件单列分母和成功率；不能与固定布局平均后宣称均通过 |

全部开始的任务都计入分母；UNKNOWN、掉落、超时、人工接管和错碗不能从成功率中删除。明确检查面不可见的遮挡应触发 uncertain，不要求系统猜测。缺陷真值由独立标注/操作者预先记录，不以模型输出作真值。

同时报告抓取成功率、有效检查率、异常漏检率、正常误报率、uncertain率、指令服从率、正确分拣率及每阶段耗时。样本足够时给中位数/P95；小样本给逐次值、范围和样本量，避免虚假精度。

`EpisodeRecord` 的后续扩展应记录 cycle/object/source IDs、mode、各阶段事件、有效/缺失面、每面分数、阈值/模型/数据/校准版本、选择的精确文本、队列代号、放置证据、独立真值和失败原因。完整照片、视频、数据集、模型仅放 Git 忽略的目录，Git 只保存协议和不含私人内容的统计。

## 10. 降级路径与下一步

- 检查动作不稳定：先减少到规则允许且能可靠看清的面/缺陷范围，公开范围限制；不声称完整表面正常。
- 指令被忽略：补相似持物状态的双指令数据，检查tokenizer与真实任务输入；必要时比较两条放置策略路由，报告实现差异。
- 交接不可靠：先规范检查终点和补充真实起点分布，不把容差放宽到未验证状态。不能可靠取消旧动作时，不开展实机分阶段执行。
- GPU/NPU数值或编译失败：选择已验证设备完成闭环，单列未通过的设备；不编造加速倍数。
- 时间不足：保留固定布局、单工件、有限检查面、受控持物交接和真实结果验证；twin扩展、RL、自由布局及全六面重抓延期。

下一次实施从W0/W1开始：指定负责人，冻结检查面和交接契约，先实现/验证录制切分与fake控制测试，再由现场人员按当次授权试录6次。此文档不启动设备、训练或运动。
